## 2. What gets created (DailyTasks-staging, from the offline synth)
VPC (2 AZ, 1 NAT gateway) · ALB with HTTPS (TLS 1.3/1.2 policy) + HTTP→HTTPS redirect · ACM certificate (DNS-validated) + Route 53 alias · ECS cluster with 3 Fargate services (api 0.25 vCPU/0.5 GB, web 0.25/0.5, worker 0.5/1 GB for Chromium) · RDS PostgreSQL 16 `t4g.micro` single-AZ, 20→50 GB gp3, encrypted, 3-day backups, private subnets · S3 bucket (private, encrypted, TLS-only, CORS pinned to the domain, `reports/` expire after 8 days) · SQS events queue + DLQ · EventBridge Scheduler group + role · Cognito user pool (no self sign-up, optional TOTP MFA) + public app client · Secrets Manager: RDS credentials, personal-data key (RETAIN) · CloudWatch log groups (14 days), 10 alarms, metric filters · SNS alarm topic. Registry stack: 3 ECR repositories.

## 4. IAM review (least privilege, from the synthesized template)
* **api task role:** S3 read + put on the app bucket (no delete — tightened in this review); Cognito `AdminCreateUser/DisableUser/EnableUser/ResetUserPassword/SetUserPassword/UserGlobalSignOut` on the one user pool; ECS Exec channels (staging only).
* **worker task role:** S3 put on `reports/*`, delete on the bucket (retention clean-up); SQS consume/send on the events queue; Scheduler create/delete/get on `schedule/dailytasks-staging/*`, `ListSchedules` (not resource-scopable), `iam:PassRole` for the scheduler role only.
* **execution roles:** ECR pull, log writes, `GetSecretValue` only on the secrets each container receives (web: none).
* Wildcard resources only where AWS requires them (`ecr:GetAuthorizationToken`, logs/ECS Exec, `scheduler:ListSchedules`).
* **Deployer** (person/CI running `cdk deploy`): uses the CDK bootstrap roles (CloudFormation execution role). Recommend a dedicated deploy role with MFA; nobody uses the root account.

## 5. Step-by-step (run only after approval)
1. **Bootstrap CDK** (once per account/region): `npx cdk bootstrap aws://<account>/<region>`
2. **Registry**: `pnpm --filter @dailytasks/aws-cdk run deploy:registry`
3. **Images**: `AWS_ACCOUNT_ID=<id> AWS_REGION=<region> scripts/push-images.sh` → note the tag.
4. **VAPID keys for staging** (never reuse in production): `pnpm push:keys` → store the private key:
   `aws secretsmanager create-secret --name dailytasks/staging/vapid-private-key --secret-string '<private>'`
5. **Deploy**:
   ```bash
   pnpm --filter @dailytasks/aws-cdk exec cdk deploy DailyTasks-staging -c region=<region> -c imageTag=<tag> \
     -c staging:domainName=<staging-domain> -c hostedZoneId=<zone-id> -c hostedZoneName=<parent-domain> \
     -c staging:vapidPublicKey=<public> -c staging:vapidPrivateKeySecretArn=<arn> -c alarmEmail=<ops-mailbox>
   ```
   Review the change set CDK prints (IAM changes) before confirming.
6. **Migrate** (one-off task, values from stack outputs): `aws ecs run-task --cluster <ClusterName> --launch-type FARGATE --task-definition <MigrateTaskDefinition> --network-configuration "awsvpcConfiguration={subnets=[<MigrateSubnets>],securityGroups=[<MigrateSecurityGroup>]}"` → check the log for `ledger verification: ok`. This first run also proves **DB TLS certificate verification** (`DB_SSL_CA_FILE`); if it fails with a TLS error, see §8.
7. **First company + admin** (no SQL): run the migrate task definition with a command override:
   `--overrides '{"containerOverrides":[{"name":"migrate","command":["node","/app/packages/database/dist/bootstrap-admin.js"],"environment":[{"name":"BOOTSTRAP_COMPANY_NAME","value":"شركة الراسيات"},{"name":"BOOTSTRAP_ADMIN_EMAIL","value":"<admin e-mail>"},{"name":"BOOTSTRAP_ADMIN_NAME","value":"<name>"}]}]}'`
   then `aws cognito-idp admin-create-user --user-pool-id <UserPoolId> --username <admin e-mail> --user-attributes Name=email,Value=<admin e-mail> Name=email_verified,Value=true --desired-delivery-mediums EMAIL` (Cognito e-mails the temporary password; the admin chooses a new one at first sign-in).
8. **Confirm** the SNS alarm subscription e-mail.
9. **Post-deploy checks**: HTTPS/PWA checklist in [DEPLOYMENT.md](DEPLOYMENT.md#https--pwa--push-checklist-after-a-deploy); `GET /health` 200; Swagger at `/api/docs`.
10. **Cognito verification**: `scripts/cognito-staging-test.mjs` + manual steps M1–M8 ([COGNITO_TESTS.md](COGNITO_TESTS.md)).
11. **Functional smoke on staging**: create a department, an employee, a task with an image; submit, approve, check Documents; request an Arabic task PDF and download it.
12. **Real-device tests**: [REAL_DEVICE_TESTS.md](REAL_DEVICE_TESTS.md) on a physical iPhone and Android phone.
13. **Visual check on staging** of the screens in [VISUAL_QA.md](VISUAL_QA.md).
14. Sign-off → only then plan production (separate approval).

## 6. Production differences (later, separate approval)
Multi-AZ `t4g.medium`, 14-day backups, deletion protection, 2 NAT gateways, api/web ×2 (autoscaling), worker 2 GB, 90-day logs, versioned bucket, termination protection, `SWAGGER_ENABLED=false`, **SES for Cognito e-mail** (Cognito's default sender is limited to ~50 e-mails/day and uses `no-reply@verificationemail.com`), production VAPID keys, AWS Budget + optional WAF rate-based rule on `/api/v1/auth/*`.

## 7. Known staging limitations
* API rate limits are kept per container (in memory); with 1 api task in staging this equals the configured limits.
* Cognito default e-mail (limits above) is acceptable for staging only.
* LocalStack-specific behaviour (non-persistent S3 in local Docker) does not apply to AWS.

## 8. Rollback for the staging deploy
* Failed ECS deployment → circuit breaker rolls back automatically.
* Bad release → `cdk deploy … -c imageTag=<previous tag>`.
* DB TLS verification failure at first migrate → temporarily remove `DB_SSL_CA_FILE` (falls back to encrypted-but-unverified TLS), redeploy, and open an issue — do not disable TLS.
* Whole environment → `cdk destroy DailyTasks-staging` (staging only). In staging the RDS instance, the S3 bucket and the Cognito user pool use `DeletionPolicy: Delete` — **no final snapshot is taken**; take a manual snapshot first if the data matters. The personal-data key secret is RETAINed and must be deleted manually if desired. (Production retains/protects all of them.)
